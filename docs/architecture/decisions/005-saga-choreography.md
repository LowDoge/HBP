# ADR-005: Saga Choreography

## Контекст

Необходим механизм координации распределенных транзакций.

## Варианты

- Choreography
- Orchestrator

## Решение

Choreography.

## Обоснование

1. Слабая связанность сервисов
2. Нет единой точки отказа
3. Естественно для Event-Driven архитектуры
4. Легкое добавление новых участников

## Последствия

- Сложнее отладка (нужна трассировка)
- Компенсирующие транзакции
- Мониторинг событий
